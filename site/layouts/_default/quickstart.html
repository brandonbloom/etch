Quickstart

Install etch, send its bootstrap prompt to an agent, then make sure the agent is allowed to invoke etch in future sessions. The command itself only prints text.

1. Install

GOEXPERIMENT=jsonv2 go install github.com/brandonbloom/etch/cmd/etch@latest

Requires Go 1.26.2+ with GOEXPERIMENT=jsonv2, plus Git.

2. Bootstrap agent context

Start your agent with the bootstrap prompt from the repo you want to configure:

Codex

codex "$(etch prompt)"

Claude Code

claude "$(etch prompt)"

The bootstrap prompt asks the agent to inspect the repo, find or create the right instruction file, and add the durable context from etch prompt --context.

Show bootstrap prompt 
{{ $prompts.bootstrap }}

To inspect the durable context directly, run:

etch prompt --context

3. Complete agent access

Some agents require command allow-listing before future sessions can invoke etch. The bootstrap agent may offer to add the right config; use one of these shapes if your tool needs an explicit rule.

etch is designed to be safe for agents to invoke with any arguments: it is scoped to the current git repo and every mutation becomes a commit.

Codex

Add to .codex/rules/etch.rules:

prefix_rule(
    pattern = ["etch"],
    decision = "allow",
    justification = "Use etch in this snapshot-style repo",
    match = [
        "etch set notes.md status done",
        "etch table row insert data.csv --after id=1 '{\"id\":\"2\"}'",
    ],
)

Claude Code

Add to .claude/settings.json:

{
  "permissions": {
    "allow": [
      "Bash(etch *)"
    ]
  }
}

4. Verify a transaction

Ask the agent to make a small structured change with etch. To check the binary directly instead, run one command from inside a Git worktree:

etch set state.json status open

The set command creates state.json, creates a commit, and materializes the new file into the checkout.

After the prompt and allow-listing are in place, future agents can use etch help and the reference when they need exact syntax.
