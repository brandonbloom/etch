Quickstart

Install etch, allow-list the command, then copy the seed prompt into your agent instructions file.

1. Install

go install github.com/brandonbloom/etch/cmd/etch@latest

2. Allow-list

Add etch to your agent's command allow-list.

etch is designed to be safe for agents to invoke with any arguments: it is scoped to the current git repo and every mutation becomes a commit.

Claude Code

Add to .claude/settings.json:

{
  "permissions": {
    "allow": [
      "Bash(etch *)"
    ]
  }
}

Codex

Add to .codex/rules/etch.rules:

prefix_rule(
    pattern = ["etch"],
    decision = "allow",
    justification = "Use etch in this snapshot-style repo",
    match = [
        "etch set notes.md status done",
        "etch table row insert data.csv --after id=1 '{\"id\":\"2\"}'",
    ],
)

3. Seed prompt

Add this to your project's CLAUDE.md or AGENTS.md:

# etch — structured file mutations

Use `etch` for all mechanical edits to data files (JSON, YAML, Markdown,
JSONL, CSV) in this repo. Do not construct patches or use sed/awk for
these operations. Each etch invocation auto-commits.

## When to use etch

- Setting/deleting frontmatter fields or JSON/YAML keys
- Appending to arrays or JSONL logs
- Replacing/appending to Markdown sections
- Opening/closing task checkboxes
- Adding list or task items
- Table operations (set cells, add/delete rows and columns)
- Creating, moving, or copying files

## Key commands

```
etch set <file> <selector> <value>               # set a field
etch delete <file> <selector>                    # delete a field
etch append <file> <selector> <value>            # append to array
etch add <file> <selector> <value>               # idempotent array add
etch remove <file> <selector> <value>            # idempotent array remove
etch section replace <file> <heading> <content>  # replace section body
etch section append <file> <heading> <content>   # append to section
etch task close <file> <text>                    # check off a task
etch task open <file> <text>                     # uncheck a task
etch task add <file> <text>                      # add a new task
etch list add <file> <text>                      # add a list item
etch create <file>                               # create a new file
etch append <file.jsonl> '{"key":"value"}'       # append JSONL record
```

## Multi-operation transactions

Group operations into a single atomic commit:

```
etch run - <<'SCRIPT'
set tasks/review.md status complete
set tasks/review.md completed "2026-05-02"
section append journal/today.md "## Log" <<EOF
- Completed review task
EOF
SCRIPT
```

## Values

Values are strings by default. Use `--json` for non-string types:

```
etch set f.json count --json 42
etch set f.json enabled --json true
etch set f.json tags --json '["a","b"]'
```

Or use assignment syntax for multiple fields:

```
etch set f.json status=done priority:=1
```

## Inline fields (Markdown)

Target Dataview-style inline fields with address flags:

```
etch set task.md done "2026-05-02" --task "Send follow-up"
etch set page.md status "reviewed" --section "## Notes" --tail
```

## Reference

Run `etch help` for full documentation. Key topics:
`etch help model` `etch help selectors` `etch help values`
`etch help fields` `etch help scripts` `etch help plans`

What this gives you

  • The agent uses etch instead of patches for mechanical edits — fewer tokens, fewer errors
  • Every mutation is an atomic git commit with an auto-generated message
  • Multiple agents can work on the same repo concurrently (optimistic locking with automatic retry)
  • No network, no process spawning, no filesystem escapes — safe to allow-list

Customize for your repo

The seed prompt above is generic. You can tailor it by adding:

  • File conventions — which directories hold what, expected frontmatter fields
  • Preferred operations — if the agent should always use scripts for multi-step updates
  • Guard patterns — e.g. "always check etch contains before mutating status fields"
